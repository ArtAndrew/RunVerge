# Execution domain contract 0.7.0

Canonical DTOs are Go types in internal/domain. JSON Schema/OpenAPI, state-machines.json and permissions.json are generated by cmd/contracts. The generator's version is authoritative; clients must preserve unknown additive response fields. The default product/app release version is independent from the wire-contract revision.

## Objects and bindings

| Object | Identity and meaning |
|---|---|
| Task | Organization-owned goal, immutable authority owner and lineage, criteria/result, shared descendant-inclusive budget |
| Run | One attempt of a Task, initiating principal and pinned published agent version |
| Operation | Durable schedulable unit in one Run/Task; monotonically increasing fencing token and bounded attempts |
| Action | One externally consequential attempt; immutable operation/task/intent/charge key and separate dispatch outcome |
| Artifact | Immutable organization/task-owned result snapshot with provenance; text up to256KiB in this implementation |
| Material / MaterialRevision | Stable editable document head / append-only content and authorship; separate from a published candidate |
| Approval | A decision for the exact Action intent hash, one version, expiry and deciding principal |
| Reservation | Immutable physical charge identity, pricing/account binding, frozen root-to-leaf scopes and cost state |
| Event | Durable organization-scoped sequence, task, type, structured data and creation time |

Composite foreign keys bind run→task, operation→run/task, action→operation/task, reservation→action/operation/task, approval→exact action/task/intent. Existence of independent IDs is insufficient. Published agent definitions, task lineage/pins and admitted cost snapshots cannot mutate in place. Cross-organization references fail before any valid command acknowledgment.

## State and concurrency

All state names/transitions are generated from domain.StateMachines. A listed edge is a shape contract, not permission to set a status directly. Guards include current policy, optimistic version, lease/fencing, parent state, budget, evidence and approval binding. Terminal Task/Run states cannot resume; a new attempt uses a new Run and shares the original Task/root budget.

An operation lease can be reclaimed with a greater fencing token after expiry. Stale workers cannot publish artifacts or change task execution state. External economic facts are ingested through a distinct trusted accounting path, even when the worker has lost ownership. There is no universal exactly-once external effect guarantee.

Approval pending→approved/denied/expired is terminal for that decision. A new/changed action, args digest, version or expired decision requires another decision. A model asking for permission is not itself an approval. Bounded ToolExecution preparation/decision/explicit dispatch is described in TOOL-EXECUTIONS.md. Revision0.7 adds native tool requests and explicit same-Run continuation in MODEL-TOOLS.md; automatic policies and arbitrary action approval workflows remain incomplete.

Cancellation prevents further admission, records a terminal task state, fences nonterminal descendant operations and preserves potential in-flight liabilities. The bounded coordinator supports nested sequence/parallel/delegate_verify and exact joins. It waits for a child's intermediate native tool request or unresolved tool effect; only the final candidate can be consumed. Task tree primitives and immutable attribution do not by themselves mark W08 complete. Bounded shared materials, explicit tool approvals and native tool selection/explicit continuation are implemented; automatic policies remain incomplete. See [COLLABORATION.md](COLLABORATION.md) and [MODEL-TOOLS.md](MODEL-TOOLS.md).

## Agent and team definitions

An AgentDefinition contains name, instructions, model, allowed tools, positive maximum task budget and an optional TeamDefinition. POST /agents supports a simple draft or a bounded team. Published member versions and the closed tree are validated before team execution. Unsupported capabilities are rejected rather than silently ignored.

Team patterns: sequence, parallel (with join), delegate_verify. Members pin agent ID/version. Bounds:1…32 members,1…32 children per expansion, max depth1…16. Join policy all or allow_partial; delegate_verify has exactly two distinct member IDs, worker then verifier. Duplicate IDs and invalid pinned versions are semantic errors. No arbitrary user graph or cycle is accepted by these constrained patterns. JSON Schema checks structure; domain.ValidateTeam checks cross-field semantics. Publication/admission validates published versions in the tenant, bounded topology, empty tool lists and pinned model profiles. Runtime also applies current authority and inherited budget. General tool/capability intersection policy is not implemented in this text-only slice.

## API compatibility and reads

Existing route names are retained; this does not promise wire compatibility across revisions. Revision0.3 changed factual money from JSON numbers to exact decimal strings, requiring matching clients. Use0.7 clients for the current collaboration/material/tool commands. New optional Task metadata preserves durable cached0.3 responses. Revision0.2 originally added Task root_id, optional parent_id, depth, financial_hold and these inspection reads:

- GET /tasks/{id}/runs
- GET /tasks/{id}/operations
- GET /tasks/{id}/actions
- GET /tasks/{id}/approvals
- GET /tasks/{id}/costs (see COSTS.md)

The four lists use envelope data+optional next_cursor, query cursor+limit(default50,max100), descending created_at/id and opaque cursors. A foreign task ID is not found, including nested reads and empty collections. Role permissions use the generated matrix; service-only billing authority is never an ordinary role permission. Existing write idempotency remains scoped to organization+principal+method/route+key+canonical input hash.

Source names and limits are explicit: goal16KiB UTF-8; instructions32KiB; name120 UTF-8 bytes; request1MiB; current JSON nesting≤32, no null, duplicate/case-alias/unknown mutation fields. Invalid raw UTF-8 and unpaired Unicode surrogate escapes are rejected before JSON decoding; they are never silently replaced before hashing. Opaque identifiers are not proof of identity. JSON Schema size annotations distinguish byte limits from Unicode character counts; cross-field/authority/business validation remains server-side.

## Delivery and evidence

State, journal/events and outbox commit together. Event allocation serializes per organization until commit, preventing a visible cursor from overtaking an earlier uncommitted event. Read reports use durable data, not the delivery stream as sole storage. API event polling is separate from MCP transport/resumption.

Generated contracts are inputs to every SDK/UI/runtime/MCP adapter, not independent reimplementations of server logic. Current adapters only advertise implemented endpoints. The bounded private MCP implementation is described in docs/MCP-ADAPTER.md; its tools call the ordinary API rather than reimplement authority or costs. Full OAuth resource-server and external action gateway acceptance remain open under docs/architecture/MCP.md and mcp-profile.json.
