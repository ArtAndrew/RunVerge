# Возможности платформы и начало работы

Версия API0.13 добавляет единый каталог поддержки, ролей и сценариев начала
работы. Он доступен в Workspace на экране **«Возможности»**, через оба SDK,
обычный HTTP/CLI и MCP. Технический формат: [CAPABILITIES.md](../contracts/CAPABILITIES.md).

Каталог отвечает на три вопроса: что реализовано, какие ограничения действуют
и с чего начать в своей роли. Он не меняет настройки и не запускает модель,
проверку соединения или инструмент. Прочтение инструкции не расширяет доступ.

## Пользователю и администратору

Откройте «Возможности» после подключения к организации. Сверху показана текущая
роль. Ниже функции разделены на поддерживаемые, ограниченные и недоступные.
Раскройте условия интересующего профиля, затем выберите сценарий:

- сотрудник — выбрать опубликованного агента, запустить задачу с пределом и
  отдельно проверить точный результат;
- разработчик агента — выбрать подготовленные модель и инструменты, создать
  агента, опубликовать версию и выполнить ограниченную пробу;
- создатель команды — закрепить версии участников, общий бюджет, срок и
  поведение при частичном результате;
- администратор — пройти планирование, проверку, требуемое согласование,
  применение и отдельную проверку подключения;
- облачный провайдер — увидеть текущие отсутствующие этапы. Готовый provider
  lifecycle пока не выпущен;
- уполномоченный агент — прочитать свою область и работать только с выданными
  назначениями, действиями и накопительными пределами.

Это шесть сценариев, а не шесть новых ролей доступа. У людей остаются
viewer/member/admin/owner; у сервисных учётных записей — viewer/member с
дополнительными ограничениями. Разрешения на конкретную задачу, подключение,
согласование и отправку сервер проверяет заново при выполнении команды.

Таблица HTTP/MCP/SDK находится в раскрываемой технической справке. Отсутствующая
команда отмечена явно. Пути `docs/` и `contracts/` относятся к файлам репозитория;
они не обещают отдельного сайта документации на адресе API.

## Агенту или разработчику

Обычный CLI работает по HTTP с учётной записью организации, без доступа к базе:

```sh
bin/platform capabilities --url https://platform.example --credentials /private/platform.json --json
```

Для локального API допустим явный loopback IP с HTTP. Для удалённого нужен
HTTPS; перенаправления не выполняются. Клиент и API должны использовать0.13.0.
Токен передают через приватный файл или предусмотренные переменные окружения,
а не аргументом команды. При ошибке чтения повторная отправка изменений не
выполняется. Примеры методов SDK:
[Python](../packages/python-sdk/README.md), [TypeScript](../packages/typescript-sdk/README.md).

HTTP: `GET /api/v1/capabilities`, без query и тела, с обычными заголовками
авторизации, организации и версии. Результат содержит текущую личность,
82 операции, 13 профилей, шесть профилей ролей и шесть сценариев начала работы.
Список операций строится из того же реестра, что OpenAPI; ссылки на MCP берутся
из зарегистрированных инструментов. SDK и Workspace указывают фактически
реализованные способы доступа. Их наличие не означает право выполнить команду.

`permission_alternatives`, `runtime_guards`, инструкции и шаблоны — описательные
данные. Это не токен, допуск отправки или решение `can_execute`. Для настройки
сервисный member может иметь отдельное точное разрешение, даже не имея
административного permission роли. Проверяются вся текущая цепочка разрешений,
срок, версии и накопительные пределы. Историческая квитанция может оставаться
читаемой после отзыва, не предоставляя права на повторную отправку.

Первый доверенный доступ создаёт владелец установки. Адреса и назначение ключа
задаёт оператор по [полным JSON-формам](CONFIGURATION-PROFILES.md). Затем
используется [обычный путь настройки](CONFIGURATION.md). Сохранено, соединение
когда-то ответило, окончательный счёт получен и результат принят — отдельные
состояния. Неизвестный отправленный эффект нельзя автоматически повторять.

## MCP и диагностика

`platform_capabilities` — новый читающий MCP tool, включённый по умолчанию.
Он не принимает аргументы организации, версии, пагинации или ключа записи.
Сервер использует текущую учётную запись транспорта и обычный API. Mutation tools
по-прежнему требуют отдельного операторского включения и текущих прав.

Удалённый MCP HTTP-клиент не получает DSN платформы. Команда `mcp-stdio` в этом
продукте является доверенным локальным сервером с доступом к PostgreSQL, а не
HTTP-прокси. Её запускает оператор с приватной учётной записью; каждое обращение
повторно проверяет доступ. Полный транспортный профиль: [MCP-ADAPTER.md](MCP-ADAPTER.md).
Полный внешний MCP OAuth onboarding этим каталогом не реализован.

Для сохранённой конфигурации используйте [doctor](DOCTOR.md). Каталог исправлений
доступен без сети и учётной записи:

```sh
bin/platform doctor --catalog --json
```

Эта команда возвращает шаблоны отдельных действий и условия, но не исполняет
их. Прочитанный каталог не подтверждает доступность поставщика, ключи worker,
правильность ответа модели, окончательный счёт или готовность выпуска.

## Проверка и оставшаяся работа

Описанный профиль проверяется отдельно от полного продукта. Сценарий нового
человека для каждой роли, широкая самостоятельная настройка, все зависимости
W11, Provider Edition, sandbox, корпоративный lifecycle, эксплуатация и выпуск
остаются в исходном плане. История проверок и
текущая приёмка: PROGRESS.md.
