# Локальная разработка

Нужны Go 1.27, PostgreSQL 18, Node.js 24 и Python 3.10+. Серверные зависимости закреплены в go.mod/go.sum; веб и SDK — в собственных package manifests и lock-файлах. Установка зависимостей выполняется до автономного запуска. По умолчанию локальный профиль использует loopback, bootstrap token и fixture:echo. Ограниченный модельный профиль и браузерный OIDC-вход настраиваются отдельно; их наличие ещё не означает готовность всей платформы к эксплуатации.

Текущая версия API —0.14.0. Границы опубликованной альфы и проверенные сценарии описаны в [SUPPORT.md](SUPPORT.md); исходники дополнительных компонентов не означают их готовность к эксплуатации. Настройка моделей и MCP через интерфейс, обычный CLI или SDK описана в [CONFIGURATION.md](CONFIGURATION.md).

## На текущем компьютере

Все команды выполняются из корня репозитория. `python3 scripts/dev.py doctor` находит скачанные в рабочую папку инструменты. Их пути не включаются в поставку и не заменяют список prerequisites для другой машины.

```sh
python3 scripts/dev.py db-init
python3 scripts/dev.py db-start
python3 scripts/dev.py build
python3 scripts/dev.py migrate
python3 scripts/dev.py bootstrap --name 'My organization' --out .local/bootstrap.json
python3 scripts/dev.py serve
```

В другом терминале:

```sh
python3 scripts/dev.py worker --concurrency 4
```

Открыть http://127.0.0.1:8080. В настройках подключения указать организацию и токен из приватного `.local/bootstrap.json`. Токен держится только в памяти страницы. Файл создаётся с правами 0600, исключён из Git и никогда не должен попадать в отчёты, скриншоты или сообщения. Повтор bootstrap создаёт отдельную организацию и требует нового имени файла; он не сбрасывает существующую.

`--concurrency` ограничивает модельный пул, default 4, допустимо 1…64. Увеличение пула не увеличивает бюджет: каждый запрос отдельно проходит общий допуск. Полная справедливость между организациями и нагрузочные цели проверяются отдельным этапом.

## Модели и вход пользователей

Модельный профиль описывает установку immutable connection через `install-model --file`, границы цены/запроса и ссылки на секреты `PLATFORM_MODEL_KEY_*`. В интерфейсе появится только установленная активная модель. До установки нет скрытого обращения к внешнему платному API. Полученный ответ остаётся непроверенным кандидатом, а стоимость — неизвестной с удержанным резервом до доверенной сверки счёта. Тарифные предположения требуется проверить для конкретного поставщика.

OIDC-вход описывает private config, HTTPS, PKCE, существующие привязки пользователей, сессии и CSRF. Для проверенного локального браузерного сценария используется отдельный TLS/IdP fixture. Обычный HTTP/Vite proxy не заменяет HTTPS origin. Ограниченные правила обязательного OIDC-входа описаны в [SECURITY.md](../contracts/SECURITY.md); SCIM, совместимость с произвольными корпоративными провайдерами и полный цикл управления сотрудниками ещё не завершены.

## Настройка подключений0.12

[Руководство настройки](CONFIGURATION.md) описывает раздел «Настройка» и `bin/platform config`: просмотр разрешённых назначений → точный план → проверка изменений → необходимое одобрение владельца → применение → отдельная проверка связи. Обычному клиенту нужен текущий платформенный токен, доступ к базе не требуется. Применение само не вызывает модель или MCP peer. Проверка модели отдельно резервирует расходы; MCP discovery допускается только для заранее одобренного бесплатного профиля и не устанавливает исполняемые инструменты.

Оператор установки отдельно регистрирует приватные назначения и ссылки на ключи командами `bin/platform install-credential-purpose --file ...` и `bin/platform install-configuration-destination --file ...` в настроенном окружении с доступом к базе. Токены и содержимое закрытых профилей не передаются через обычный публичный API. Полный контракт и17 реализованных маршрутов: [CONFIGURATION.md](../contracts/CONFIGURATION.md).

## Работа команд и материалов

Команды агентов описывают вложенные sequence/parallel/delegate_verify и пределы дерева. [Приёмка результата](../contracts/COLLABORATION.md) связывает решение с точной версией материала. Замечание не запускает модель: новая попытка требует отдельного подтверждения возможного расхода и сохраняет прежние обязательства. Синтетическая команда из fixture:echo проверяет протокол, а не качество модели или реальный биллинг. Командный итог имеет обзор участников и отдельно доступный точный исходник. [Материалы](../contracts/MATERIALS.md) редактируются как append-only версии: конфликт409 сохраняет локальный текст, слияние выполняется явно, публикация и приёмка — отдельные действия. Публикация не вызывает модель и не меняет Run/расходы. Несохранённый текст временно хранится только в ограниченной RAM и восстанавливается после новой проверки той же личности и доступа; перезагрузка страницы его теряет.

## Частный MCP-профиль

Серверные исполняемые файлы написаны на Go; отдельный runtime Python/Node для этого адаптера не требуется. [MCP-ADAPTER.md](MCP-ADAPTER.md) описывает ограниченную ревизию протокола, клиент и незавершённый полный OAuth-профиль. Сервер HTTP по умолчанию не включает MCP. Для stdio явно передайте приватный файл текущего principal:

```sh
bin/platform mcp-stdio --credentials .local/bootstrap.json
```

Нужен `DATABASE_URL` в окружении; локальный helper передаёт его без вывода: `python3 scripts/dev.py mcp-stdio --credentials .local/bootstrap.json`. STDOUT занят протоколом. По умолчанию доступны50 инструментов чтения. Изменения требуют отдельного операторского списка `--allow-mutations` из30 точных имён; это не выдаёт principal дополнительных прав. Контур настройки добавляет10 чтений и7 команд записи. Не подставлять в executable/arguments значения из ответа модели.

Для HTTP добавьте `serve --mcp --tls-cert ... --tls-key ...`; допустим отдельно доверенный TLS proxy к loopback. Без TLS/явного proxy запуск отклоняется. `--mcp-mutations` включает конкретные изменяющие инструменты, `--mcp-origins` задаёт точные разрешённые browser origins. Cookies для MCP не принимаются. Это приватный platform-token профиль; браузерный OIDC не превращает его в MCP OAuth resource-server. Внешние side effects через клиент запрещены без общего execution gateway.

## Явные действия с инструментами

Доверенный оператор устанавливает private connection через `python3 scripts/dev.py install-tool --file .local/tool-profile.json`. Образец формы: tool-profile.example.json. Это шаблон с нерабочим адресом и заменяемой организацией, а не готовая интеграция. Секрет хранится отдельно в окружении worker по имени `PLATFORM_TOOL_KEY_*`; endpoint, ссылка на ключ и локальный CA не выдаются клиентам через каталог. Для стандартных MCP-аргументов и текстовых ответов доступен отдельный [профиль чтения](MCP-READ.md); существующий custom action contract сохраняется для записывающих действий.

[TOOL-EXECUTIONS.md](../contracts/TOOL-EXECUTIONS.md) задаёт точный сценарий: подготовить действие и резерв → согласовать → явно отправить → прочитать наблюдаемый исход. Согласование само не вызывает сеть. После неизвестного исхода повторная отправка запрещена; оператор может отдельно записать наблюдение с причиной и evidence digest. Это не подтверждает счёт и не принимает исходный материал. Интеграция требует контракта `agent_platform_action_v1`; обычный HTTP 200 или успешный MCP result недостаточен.

Миграции001–020 уже применены к сохранённому локальному профилю. Их нельзя редактировать; дальнейшие изменения схемы оформляются новой миграцией. Проверка018→019+020 (internal historical reference omitted) сохранила все прежние проекции строк, guards и состояния последовательностей; это не проверка резервного восстановления.

## Native model tools

Агент с подключённой моделью может выбрать до16 установленных инструментов через `CreateAgent.tools`. Сервер закрепляет их текущие версии, схемы и profile digests; нельзя подать свой endpoint или подменить readonly pins. Модель получает native function tools. Её запрос сохраняется как промежуточный пакет, а не исполняется как текстовая команда.

[MODEL-TOOLS.md](../contracts/MODEL-TOOLS.md) описывает exact proposal → prepare → approve → dispatch → наблюдение всех исходов → отдельное подтверждённое продолжение модели. Новый шаг использует тот же Run и сохранённую историю, не снимая прежние резервы. Есть два ограниченных режима автоматизации с отдельными task-scoped разрешениями, текущими правами и накопительными лимитами; полный продуктовый профиль политик и sandbox остаются незавершённым объёмом. Для локальных проверок используйте только явно установленные synthetic fixtures; примеры не содержат ключей платного поставщика.

## Явный запуск синтетических peers

Тестовые peers не запускаются вместе с обычным сервером и не вызывают платные модели. После bootstrap выполните в отдельных терминалах из корня репозитория:

```sh
python3 scripts/dev.py fixture action
python3 scripts/dev.py fixture read
python3 scripts/dev.py fixture model
```

Дождитесь сообщения готовности action peer перед запуском read peer: они используют один локальный тестовый сертификат. Каждый процесс остаётся в своём терминале. Команды также работают из другой рабочей папки при указании абсолютного пути к `scripts/dev.py`; корень определяется по расположению самого файла. Нужна POSIX-система, Python и `openssl` для первого TLS-сертификата.

Установите созданные профили и запустите **один** worker с явным подключением тестовых ключей:

```sh
python3 scripts/dev.py install-tool --file .local/tool-fixture-profile.json
python3 scripts/dev.py install-tool --file .local/read-fixture-profile.json
python3 scripts/dev.py install-model --file .local/native-model-profile.json
python3 scripts/dev.py worker --fixture-credentials --concurrency 4
```

Если worker уже работает, сначала завершите именно его и затем запустите с нужными настройками. `--fixture-credentials` читает только три известных приватных файла и передаёт значения в окружение дочернего процесса. Параметр не поддерживается у сервера, не исполняет содержимое файлов и не заменяет производственный secrets broker. Без параметра ключи автоматически не загружаются. Символические ссылки, открытые права доступа, неизвестные имена переменных и конфликт с уже переданным ключом отклоняются. `.local` должен иметь права0700, файлы ключей0600.

Текущий браузерный сценарий требует собранных web/SDK, работающих API/worker, Playwright и этих явно установленных peers:

```sh
node web/scripts/smoke-automation-live.mjs --preflight-only
node web/scripts/smoke-automation-live.mjs
node web/scripts/smoke-automation-reopen.mjs
```

Проверка `--preflight-only` читает только версию health и завершается до чтения credentials, загрузки Playwright и создания output-каталогов. Она не доказывает наличие прав или доступность peers. Без этого флага сценарий создаёт новую синтетическую задачу, разрешает только подготовку действия, затем отзывает разрешение через интерфейс. Проверяет отмену доказанно неотправленного действия и освобождение резерва до естественного истечения срока. Вторая команда только открывает тот же результат и проверяет отсутствие изменений. Отчёты и снимки находятся в `.local/qa/automation/`; другой каталог задаёт `AGENT_PLATFORM_QA_OUTPUT`. Playwright можно указать через `WORKSPACE_PLAYWRIGHT_PATH`, браузер — `WORKSPACE_BROWSER_PATH`, Python — `WORKSPACE_PYTHON`. Старые фазовые отчёты0.8 не перезаписываются.

SDK-сценарии можно сначала проверить без создания задач:

```sh
python3 tests/sdk/run_platform_e2e.py --preflight-only
python3 tests/sdk/run_platform_e2e.py --report .local/qa/sdk-report.json
```

Первая команда читает состояние API и наличие установленных синтетических профилей. Она не проверяет доступность самих peers и не создаёт отчёт или задачи. Вторая выполняет20 сценариев обоих SDK и сохраняет тестовые записи; каталог отчёта создаётся автоматически. Публичный manifest находится в `tests/fixtures/tool-scenarios.json`, поэтому вручную создавать `.local/tool-fixtures.json` не требуется.

## Проверки

```sh
python3 scripts/dev.py test
python3 scripts/verify_foundation.py --report-name core-0.12.0-new-run
python3 tests/security/test_http_boundaries.py --preflight-only
python3 tests/security/test_http_boundaries.py --org-a .local/bootstrap.json --org-b .local/bootstrap-b.json --with-worker

```

Первая команда запускает Go race detector и настоящие PostgreSQL integration tests, включая аварийное завершение процесса и модельные сценарии с локальным HTTP fixture. Для integration tests используются отдельные временные схемы, удаляемые после проверки. Вторая воспроизводит проверки основы, двух SDK, веб-сборки, локальных инструментов и переносимого модельного peer, сохраняет логи и хеши исходников в docs/evidence. Для нового прогона задайте новое имя отчёта, чтобы сохранить предыдущие доказательства. Две health-проверки с `--preflight-only` не читают файлы credentials и ничего не создают. Полные boundary-сценарии требуют живой сервер, worker и две разные тестовые организации; они создают постоянные тестовые записи. Это проверки локального fixture, не реального платного провайдера. SDK и контрактные live-сценарии дополнительно описаны в tests/sdk/ и tests/contracts/.

Для генерации интерфейсных схем из Go DTO: `go run ./cmd/contracts`. Не редактировать полученные domain.schema.json/OpenAPI вручную. Ещё не реализованные интерфейсы остаются в полном архитектурном плане; они не должны появляться в SDK как якобы рабочие.

## Остановка

Остановить сервер и worker сигналом завершения/Ctrl+C, затем `python3 scripts/dev.py db-stop`. Каталог `.local/postgres` содержит данные и не удаляется при остановке. Системные службы не создаются. Резервное копирование и production recovery будут реализованы и проверены отдельным этапом W14.


## Участники и локальный доступ0.9

Раздел «Участники» доступен владельцу/администратору. Создание выделяет новую
учётную запись и членство в текущей организации; приглашение не отправляется,
вход не выдаётся. Роль/состояние изменяются по точной версии с причиной.
Свои права изменяет другой администратор; чужого владельца меняет владелец.

Для локальной проверки доверенный оператор хоста может выдать краткий вход:

```text
python3 scripts/dev.py issue-token --organization <organization_id> --principal <principal_id> --out .local/new-member.json --ttl 1h
```

Команда требует новую приватную запись файла и не печатает токен. При ошибке
записи она пытается отозвать выданный вход. Транзакционная атомарность БД и
файловой системы при аварийном выключении этой командой не гарантируется.
Токен идентифицирует глобального principal; organization_id проверяет активное
членство и задаёт контекст файла, но не делает сам токен привязанным к одной
организации. Для свежесозданного principal существует только одно членство.
Корпоративный OIDC подключается отдельно; пользователи не получают этот CLI
через HTTP/MCP. Полный автоматический корпоративный onboarding остаётся открыт.

Поддерживаемые opt-in проверки IAM используют текущий SDK и версию API. Сначала можно проверить только health без credentials и без создания участников:

```sh
python3 tests/sdk/run_membership_e2e.py --preflight-only
node web/scripts/smoke-members-live.mjs --preflight-only
```

Для полной проверки нужны локальный trusted `issue-token`, действующий владелец и новые пути отчётов. Она создаёт и затем отключает синтетических участников; задачи и модельные вызовы не запускаются:

```sh
python3 tests/sdk/run_membership_e2e.py --report .local/qa/members-new-run.json
AGENT_PLATFORM_QA_OUTPUT=.local/qa/members-browser-new-run node web/scripts/smoke-members-live.mjs
```

Команда `npm --prefix web run test:browser -- --preflight-only` также проверяет только health. Полный `test:browser` требует собранных web и TypeScript SDK, Playwright, действующего bootstrap и worker; он создаёт синтетическую fixture-задачу. API URL/credentials/output можно задать через `AGENT_PLATFORM_URL`, `AGENT_PLATFORM_CREDENTIALS`, `AGENT_PLATFORM_QA_OUTPUT`. Старые `WORKSPACE_URL` и `WORKSPACE_BOOTSTRAP` сохраняются как совместимые имена для этого сценария. Для каждого полного прогона выбирайте новый output-каталог.

«Отозвать прежние входы» лишает старые ключи/cookies доступа к этой организации.
Это отдельная операция от отзыва разрешения автоматической задачи. Отключение
участника также лишает прежнее выполнение полномочий; уже отправленные/неизвестные
эффекты сохраняют финансовые обязательства. [Контракт](../contracts/MEMBERSHIPS.md).

## Политика входа и служебные аккаунты0.10

В «Безопасности» доступны правила входа, служебные аккаунты, метаданные ключей и аудит. Только человек-владелец меняет политику; администратор управляет аккаунтами. Смена SSO требует настоящего браузерного входа владельца у настроенного провайдера.

```text
python3 scripts/dev.py issue-service-token --organization ORG --principal SERVICE --role-ceiling viewer --ttl 1h --reason "Read-only integration" --out .local/new-service.json
python3 scripts/dev.py mcp-stdio --credentials .local/new-service.json
```

Файл новый и приватный0600; токен не печатается. Отзыв/истечение ключа запрещает новые запросы; отключение аккаунта или доступа приложений отзывает разрешение уже принятого выполнения. Повторное включение не оживляет старые ключи или работу. Максимальный срок применяется к новым ключам.

Аварийный возврат к mixed — явная команда хоста `python3 scripts/dev.py recover-login-policy --organization ORG --reason "Recorded recovery"`. Она сохраняет audit, не возвращает старые токены и не является сетевым обходом SSO. Подробности: [SECURITY.md](../contracts/SECURITY.md).


## События и текущая версия API0.14

Снимки, точные курсоры и replay появились в0.11. Текущие UI и SDK отправляют обязательный `X-Platform-API-Version: 0.14.0` автоматически. Прямой HTTP-клиент должен добавить его явно; текущую версию сообщает `GET /api/v1/compatibility`. Несовместимый запрос не исполняет команду и не заменяет сохранённый idempotency-ответ. При обновлении локального профиля обновляйте сервер, worker, UI и SDK согласованно.

Поток восстанавливается только для чтения. При устаревшей истории интерфейс просит обновить снимок, сохраняя черновик; он не повторяет согласования, запуск или отмену. `python3 scripts/dev.py advance-event-replay --organization ORG --task TASK --after DECIMAL --reason "Recorded replay boundary"` — операторская команда с доступом к БД и обязательной причиной; она двигает только логическое окно, ничего физически не удаляет.
