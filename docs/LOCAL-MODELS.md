# Локальная модель без оплаты API

Профиль `operator_unmetered_local` в API0.14 позволяет администратору явно
задать нулевой тариф API. Стоимость компьютера, GPU, электричества и времени
при этом не измеряется. Чтение ответа не становится окончательным счётом
или подтверждением правильности ответа.

## Предварительная настройка

Установите и запустите управляемый вами локальный сервер модели на
`127.0.0.1`. Нужен совместимый endpoint `/v1/chat/completions` и конкретная
уже установленная модель. Веса и сервер модели не входят в пакет RunVerge.
Не включайте облачную маршрутизацию, если нужен полностью локальный режим:
сам loopback-адрес не доказывает отсутствие обращения к платному поставщику.

Создайте приватный файл профиля. В примере замените организацию, порт и
имя модели на свои. Не помещайте файл, ключи и данные базы в Git.

```json
{
  "id": "local_qwen",
  "organization_id": "YOUR_ORGANIZATION_ID",
  "version": 1,
  "model": "qwen2.5:1.5b",
  "accounting_mode": "operator_unmetered_local",
  "provider_account": "owned-local-model",
  "price_version": "operator-zero-api-v1",
  "endpoint": "http://127.0.0.1:11434/v1/chat/completions",
  "credential_environment": "PLATFORM_MODEL_KEY_LOCAL",
  "max_charge_microusd": 0,
  "input_microusd_per_million": 0,
  "output_microusd_per_million": 0,
  "fixed_microusd": 0,
  "max_input_tokens": 4096,
  "max_input_bytes": 16384,
  "max_output_tokens": 256,
  "max_output_bytes": 16384,
  "timeout_milliseconds": 60000,
  "token_limit_field": "max_tokens",
  "allow_insecure_loopback": true,
  "bound_assumptions": "Operator declares zero API tariff for owned local inference. Hardware and electricity costs are unmeasured; input token bound is an assumption, not inferred from bytes.",
  "active": true
}
```

Установите профиль через готовый бинарный файл:

```sh
/absolute/installation/bin/platform install-model --file /absolute/private/local-model.json
```

`DATABASE_URL` задаётся приватно для выбранной базы. Worker получает значение
переменной `PLATFORM_MODEL_KEY_LOCAL` отдельно от профиля. Если локальный
сервер игнорирует Bearer, используйте явно не секретную локальную строку;
она не создаёт аутентификацию. Сервер с настоящей проверкой ключа требует
своего действительного ключа. Текущий интерфейс worker всё ещё требует эту
переменную и для локального сервера без Bearer-аутентификации.

Выберите модель при создании агента и опубликуйте его версию. В форме
показываются тариф и ограничения. При создании задачи задайте число попыток
и общий срок. Денежный бюджет остаётся положительным: он также ограничивает
платные инструменты и подзадачи. Новый тариф требует новой версии профиля;
ранние задачи сохраняют прежнюю привязку и не переводятся на него автоматически.

## Какие ограничения действуют

- Входной запрос ограничен байтами; граница входных токенов — предположение
  профиля. Сервер получает запрашиваемый предел выходных токенов; ответ и
  возвращённое usage проверяются перед сохранением.
- Ограничены размер сохраняемого результата, время ожидания, число попыток,
  модельных ходов и инструментальных действий, общий срок задачи.
- Финансовые блокировки и отзыв доступа действуют и при нулевом тарифе.
  Платные инструменты сохраняют собственные тарифы и общий бюджет дерева.
- `worker --concurrency` ограничивает этот процесс worker. Настройки
  параллельности локального сервера задаются отдельно. Глобальная физическая
  квота CPU/GPU/памяти пока не реализована; timeout клиента не доказывает,
  что вычисление на сервере остановилось.

## Что означает неизвестная операция с суммой 0

RunVerge сохраняет идентичность попытки и нулевой резерв до вызова.
Состояние `unknown` не исчезает от нулевой суммы. Счётчик ожидающих сверки
операций учитывает всю задачу с подзадачами и все страницы. Поэтому денежный
итог 0 может соседствовать с ненулевым счётчиком. Потерянный ответ не вызывает
автоматический повтор. Новая попытка требует отдельного явного согласия и
не сбрасывает счётчики или историю.

Эта инструкция относится к ограниченному локальному профилю. Установка
корпоративного общего inference-сервера, учёт аппаратных затрат, жёсткие
ресурсные квоты и production-восстановление остаются отдельными работами.
