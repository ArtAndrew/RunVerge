# Подключение MCP-инструмента чтения

Поддерживаемый срез: стандартные аргументы `tools/call`, от1 до16 текстовых
блоков, HTTPS с конечным JSON/SSE-ответом, протокол2026-07-28. Для сервера
на Go SDK1.8.0 требуется явно включённый `Stateless:true`. Произвольные
старые серверы, OAuth и ответы с изображениями/ресурсами пока не входят в
проверенный профиль. Результаты проверки сохранены в исходном репозитории:
`docs/evidence/MCP-READ-TEXT-0.13.md`; для работы установленного пакета этот
отчёт не требуется.

## Действия администратора

1. Выберите конкретный сервер и инструмент, его схему аргументов, организацию,
   способ аутентификации и верхнюю границу стоимости. Описание инструмента
   на сервере помогает с настройкой, но не выдаёт ему права.
2. Создайте приватный файл `ToolConnection` по форме ниже. Для стандартного
   текстового чтения установите `transport:"mcp_https"`,
   `result_contract:"mcp_read_text_v1"`, `tool.effect:"read"` и точное
   `remote_tool`. `endpoint` — точный HTTPS-адрес без query/fragment.
   Укажите собственные tool ID, организацию, версию, provider/price version,
   схему, ограничения ввода/вывода и таймаут. `input_schema_digest` можно
   опустить: установщик вычислит SHA-256 точной строки `input_schema_json`.
   Если указываете digest явно, он должен совпадать с этой строкой.
3. При необходимости укажите `credential_environment` — имя переменной
   окружения worker с токеном. Сам токен не помещается в профиль или каталог.
   `trusted_ca_pem` содержит только сертификат доверенного CA; приватный ключ
   сервера туда не входит. Внутренний адрес требует осознанного
   `allow_private_network:true`; это не заменяет сетевую изоляцию.
4. Установите профиль командой установленного продукта:

   ```sh
   chmod 600 /absolute/private/tool-profile.json
   /absolute/installation/bin/platform install-tool --file /absolute/private/tool-profile.json
   ```

   Файл должен быть обычным, принадлежать текущему пользователю и не давать
   группе или другим пользователям доступ; символическая ссылка не подходит.
   Команда использует приватно настроенный `DATABASE_URL`. Она регистрирует
   профиль; сам инструмент при установке не вызывается. Изменённая конфигурация
   требует новой версии, а ранее подтверждённое намерение сохраняет старые pins.

## Форма профиля чтения

Это шаблон для собственного сервера, а не готовая интеграция. Замените
организацию, endpoint, `remote_tool`, схему и описание реальными значениями.
Пример предполагает явно подтверждённый оператором нулевой тариф и разрешает
согласование тем же уполномоченным пользователем. Для обязательного отдельного
согласующего задайте `require_distinct_approver:true` и подготовьте его доступ.

```json
{
  "tool": {
    "id": "read_document",
    "organization_id": "YOUR_ORGANIZATION_ID",
    "version": 1,
    "name": "Read an approved document",
    "description": "Template only: replace the destination and argument schema with the reviewed read-only service contract.",
    "effect": "read",
    "destination": "Owned document service",
    "provider": "owned-document-service",
    "price_version": "operator-zero-api-v1",
    "max_charge_microusd": "0",
    "input_schema_json": "{\"type\":\"object\",\"properties\":{\"document_id\":{\"type\":\"string\",\"maxLength\":128}},\"required\":[\"document_id\"],\"additionalProperties\":false}",
    "require_distinct_approver": false,
    "timeout_seconds": 10,
    "max_input_bytes": 4096,
    "max_output_bytes": 65536,
    "active": true
  },
  "transport": "mcp_https",
  "result_contract": "mcp_read_text_v1",
  "endpoint": "https://mcp.example.invalid/mcp",
  "remote_tool": "read_document",
  "allow_private_network": false
}
```

Если сервер требует токен, добавьте на верхнем уровне
`"credential_environment":"PLATFORM_TOOL_KEY_DOCUMENTS"` и задайте значение
этой переменной приватно в окружении worker до его запуска. Для внутреннего
адреса отдельно разрешите `allow_private_network`; при собственном CA добавьте
`trusted_ca_pem` с PEM-сертификатом доверенного CA. Проверка TLS остаётся
включённой. Публичный MCP-каталог не заменяет проверку назначения оператором.

`MaxOutputBytes` для этого профиля должен быть не меньше4: даже пустой текст
сохраняется как `[""]`. Число в `max_charge_microusd` — десятичная строка.
Явный тариф `"0"` допустим для собственного сервиса, но означает предположение
оператора о тарифе, а не измеренную стоимость электричества и оборудования.
`effect:"read"` также является доверенной классификацией; RunVerge не может
превратить произвольный вредоносный сервер в безопасный режим чтения.

## Действия пользователя

В задаче с доступным для проверки кандидатом выберите зарегистрированный
инструмент в Workspace, задайте аргументы по его схеме и подготовьте действие.
Проверьте точные аргументы, назначение и лимит, подтвердите действие и отдельно
отправку с учётом стоимости. Автоматическое выполнение требует отдельного
разрешения задачи; одно подключение сервера его не включает.

Исполнитель сохранит прочитанные блоки как массив строк в артефакте,
например `["Первый раздел","Второй раздел"]`. Это позволяет отличить
границы блоков и пустой результат. Данные остаются непроверенным материалом;
успешное чтение не принимает исходный результат задачи за пользователя.
Дальнейший анализ моделью и приёмка имеют собственные разрешения и лимиты.

Если сервер сообщил ошибку чтения, сохранится наблюдение с состоянием
`rejected`. Если ответ потерян или некорректен, состояние останется `unknown`;
исполнитель не отправит то же действие повторно автоматически. Финансовая
неопределённость учитывается отдельно от результата чтения.

## Что проверено непосредственно

Установленный пакет macOS arm64 прочитал пример документа с отдельного
сервера на upstream Go SDK, сохранил артефакт и точную квитанцию после
перезапуска PostgreSQL/API/worker. Чтение было выбрано проверочным сценарием
от имени владельца задачи. Это не проверка удобства другим человеком и не
доказательство самостоятельного выбора инструмента настоящей моделью.
