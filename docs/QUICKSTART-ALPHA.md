# Первый результат в RunVerge

Язык интерфейса alpha.4 выбирается в верхней панели (**Interface language**): русский, английский, испанский, бразильский португальский, немецкий, французский и упрощённый китайский. Переключение сохраняет текущую работу; тексты задач и ответы модели остаются на исходном языке. Подробнее: [языки интерфейса](LANGUAGES.md).

Профиль первой альфы: один владелец, локальный доступ и только тестовые данные. Полное восстановление и обновление существующих баз пока не поддерживаются как готовые возможности; сохраняйте нужные результаты отдельно. Не используйте эту установку как публичный командный сервис.

Инструкция для API 0.14 и alpha.4: установка macOS arm64, PostgreSQL 18
и один пользователь-владелец. Выберите локальную модель или текстовую модель
через OpenRouter. Сквозной сценарий OpenRouter проверен автоматизированным
прогоном оператора; независимое тестирование интерфейса новыми пользователями
ещё предстоит.

Нужны готовый native-пакет из доверенного источника, его контрольная сумма
и отдельная пустая база PostgreSQL. PostgreSQL устанавливается отдельно.
Для локального варианта нужен сервер с endpoint `/v1/chat/completions`, например
Ollama и `qwen2.5:1.5b`; модель и её веса обслуживаются отдельно.
Для OpenRouter локальный сервер и GPU не нужны: пользователь создаёт аккаунт
и свой ключ по [инструкции подключения](OPENROUTER.md). Бесплатные модели
могут быть недоступны из-за ограничений провайдера.
Go и Node.js для запуска готового пакета не нужны. Необязательный помощник
ввода ключа OpenRouter использует Python 3; ключ также можно сохранить в
приватном файле через локальный редактор.

## 1. Установить пакет в новый каталог

В примерах замените абсолютные пути своими. Родитель каталога установки
должен существовать и не разрешать запись другим пользователям. Сам каталог
установки должен быть новым. При ошибке команды остановитесь и разберите её;
не продолжайте следующие шаги вслепую.

До первого запуска скачанного бинарного файла проверьте контрольную сумму
пакета по доверенному каналу. `EXPECTED_HASH` ниже — доверенная SHA-256 файла
`bundle.json`, а не произвольно вычисленное значение из того же неизвестного
архива. Для локальной сборки используйте отчёт доверенной сборки.

```sh
/absolute/extracted-bundle/bin/platform version
/absolute/extracted-bundle/bin/platform bundle inspect --source /absolute/extracted-bundle --manifest-sha256 EXPECTED_HASH
/absolute/extracted-bundle/bin/platform bundle install --source /absolute/extracted-bundle --destination /absolute/runverge-installation --manifest-sha256 EXPECTED_HASH
/absolute/runverge-installation/bin/platform bundle verify --source /absolute/runverge-installation --manifest-sha256 EXPECTED_HASH
```

В результате проверки ожидаются нужные версия API, `darwin`, `arm64` и
`installed:true` у последней команды. Проверка файлов не подтверждает
подлинность издателя сама по себе. Установка создаёт только файлы приложения;
база, организация, модель и фоновые службы автоматически не создаются.
Подробности и действия после прерванной установки описаны в `RUNNING.md`
внутри пакета; в исходном репозитории это `docs/NATIVE-BUNDLE.md`.

## 2. Подготовить отдельные приватные настройки

Создайте новый каталог вне установки и Git. Выбирайте существующего родителя,
принадлежащего вашему пользователю:

```sh
umask 077
mkdir -m 700 /absolute/runverge-private
```

В локальном редакторе создайте там файл `runtime.env`. Он должен содержать
только ваши доверенные настройки shell, например:

```sh
DATABASE_URL='REPLACE_WITH_THE_CONNECTION_STRING_FOR_YOUR_NEW_DATABASE'
PLATFORM_MODEL_KEY_LOCAL='local-no-auth'
```

Для OpenRouter в `runtime.env` нужна только строка `DATABASE_URL`.
Его ключ сохраняется отдельно и загружается только исполнителем.

Замените строку подключения приватно в редакторе. Не вводите пароль базы
в командной строке и не публикуйте этот файл. Строка `local-no-auth` подходит
только для управляемого вами сервера модели, который игнорирует Bearer-токен:
она не создаёт аутентификацию. Если сервер проверяет ключ, задайте настоящий
ключ локально. Worker требует непустую переменную и для модели без авторизации.

```sh
chmod 600 /absolute/runverge-private/runtime.env
set -a
. /absolute/runverge-private/runtime.env
set +a
```

Команда `.` исполняет shell-файл, поэтому используйте только файл, который
создали и проверили сами. Установленный `platform` не читает `runtime.env`
автоматически. Эту загрузку нужно повторить в каждом терминале, где вы
запускаете команду с доступом к базе или worker.

## 3. Создать организацию и подключить модель

Убедитесь, что `DATABASE_URL` указывает именно на новую выделенную базу:
`migrate` изменяет выбранную базу. Это не инструкция обновления действующей
установки.

```sh
/absolute/runverge-installation/bin/platform migrate
/absolute/runverge-installation/bin/platform bootstrap --name 'My organization' --budget-microusd 1000000 --out /absolute/runverge-private/bootstrap.json
```

`bootstrap` создаёт организацию, владельца и его токен. Он не создаёт агента.
Бюджет `1000000` здесь означает лимит 1 USD, а не оплату или списание.
Повтор команды создаёт другую организацию; для входа в существующую используйте
сохранённый файл. Файл результата должен быть новым и создаётся с правами 0600.

Откройте `bootstrap.json` локально. Для следующих шагов нужны поля
`organization_id` и `token`; `principal_id` в форму подключения не вводится.
Не выводите токен в общие логи, снимки экрана или сообщения.

**Если выбрали OpenRouter:** после создания организации настройте профиль и ключ
по [OPENROUTER.md](OPENROUTER.md), используя свой `organization_id`. Пропустите
локальный профиль ниже. API получает настройки базы; ключ OpenRouter загружайте
только в отдельном терминале worker, как показано в инструкции подключения.

**Если выбрали локальную модель:**

Создайте `/absolute/runverge-private/local-model.json` по полному примеру
из [LOCAL-MODELS.md](LOCAL-MODELS.md). Замените `organization_id` на значение
из вашего `bootstrap.json`, имя модели и порт — на фактически работающие.
Выберите `accounting_mode:"operator_unmetered_local"` только для собственного
локального inference с объявленным нулевым API-тарифом. Все тарифные значения
в этом профиле должны быть числом `0`. `credential_environment` должно точно
совпадать с `PLATFORM_MODEL_KEY_LOCAL` в окружении worker.

```sh
chmod 600 /absolute/runverge-private/local-model.json
/absolute/runverge-installation/bin/platform install-model --file /absolute/runverge-private/local-model.json
```

Файл должен принадлежать текущему пользователю, быть обычным файлом без
символической ссылки и не давать доступ группе или остальным пользователям.
При успехе команда сообщает ID и версию установленного подключения. Она
регистрирует профиль, но не проверяет получение ответа от модели.

## 4. Запустить сервер и исполнителя

В первом терминале, где уже загружен `runtime.env`, запустите:

```sh
/absolute/runverge-installation/bin/platform serve
```

Оставьте этот терминал открытым. Во втором терминале отдельно загрузите те же
настройки и запустите один worker. Для OpenRouter загрузите также приватный файл
ключа по [инструкции подключения](OPENROUTER.md); пример ниже предназначен для
локальной модели:

```sh
set -a
. /absolute/runverge-private/runtime.env
set +a
/absolute/runverge-installation/bin/platform worker --concurrency 1
```

`--concurrency 1` ограничивает параллельность этого процесса. Это не квота GPU
и не настройка параллельности Ollama. При изменении переменных окружения
перезапускайте только свой worker в его терминале; уже работающий процесс
новые переменные из другого терминала не получает.

Откройте `http://127.0.0.1:8080`. Если порт занят, используйте, например,
`serve --listen 127.0.0.1:8081` и этот же порт в браузере. Не подключайте
одновременно две установки к одной базе, чтобы обойти ошибку запуска.
Данный профиль слушает только loopback; общий удалённый доступ требует отдельной
настройки HTTPS и идентификации.

## 5. Войти и создать настоящего агента

В Workspace нажмите **«Подключить пространство»**. Заполните:

| Поле | Значение |
|---|---|
| Адрес API | `/api/v1`, если страница открыта с запущенного сервера |
| Организация | `organization_id` из вашего приватного `bootstrap.json` |
| Токен доступа | `token` из того же файла |

При этом способе входа браузерное приложение держит токен только в памяти
страницы; в `localStorage` запоминаются организация и выбранный язык. После перезагрузки
страницы войдите снова; повторять `bootstrap` не нужно. Приватный исходный
файл с токеном остаётся у вас на диске.

В alpha.4 после подключения появляется подсказка первого запуска: **настроить агента → опубликовать версию → перейти к первой задаче**. Кнопка **«Использовать заготовку агента»** заполняет название и инструкции на выбранном языке; их можно изменить перед сохранением. Выбор заготовки не вызывает модель.

Откройте **«Агенты» → «Создать агента»**. Оставьте тип **«Один агент»**, задайте
название «Редактор инструкции», лимит задачи `1.00` USD и инструкции:

> Пиши короткие инструкции на русском языке. Используй только предоставленные
> факты. Не добавляй вымышленные сведения. Перед итогом проверяй каждый пункт
> требований пользователя.

В поле **«Модель»** проверьте подключённую `qwen2.5:1.5b` или вашу модель.
В исходниках после alpha.1 подготовленный локальный профиль с явно заданным
нулевым тарифом подставляется автоматически; платный профиль нужно выбрать
явно. В выпущенной 0.14.0-alpha.1 модель необходимо выбрать вручную вместо
`fixture:echo`: это тестовое повторение входа, не интеллектуальная работа.
Для первого задания оставьте
инструменты пустыми. Нажмите **«Сохранить черновик»**, затем **«Опубликовать»**
на карточке агента. Только опубликованная версия доступна для задач.

## 6. Получить и проверить результат

Откройте **«Задачи» → «Новая задача»**, выберите опубликованного агента,
бюджет `1.00`, предел попыток `2` и срок выполнения `1` час. Пример задания:

> Напиши инструкцию для сотрудника из трёх коротких пунктов. Факты:
> AI готовит черновик; сотрудник проверяет его; сотрудник принимает результат
> или возвращает его на доработку. Не добавляй других фактов.

**«Создать задачу» запускает первую попытку**: сервер сохраняет задачу,
а работающий worker вызывает выбранную модель. Входной бюджет должен быть
положительным даже при тарифе модели 0: это общий предел задачи и возможных
платных инструментов. Модель и оборудование при этом не объявляются
бесплатными; стоимость оборудования RunVerge пока не измеряет.

Дождитесь состояния **«Нужен ваш ответ»** и прочитайте черновик. Проверьте
все три пункта и отсутствие придуманных фактов. Небольшая локальная модель
может не выполнить инструкцию; появление текста само по себе не означает
успех задания.

Если хотите проверить MCP-чтение, выполните следующий раздел, пока черновик
ждёт решения. Затем выберите решение:

- **«Принять результат»** — сохранить приёмку этой точной версии.
- **«Запросить доработку»** — записать замечание и приостановить задачу.
  Затем отдельно нажмите **«Подготовить новую попытку»**, заполните причину,
  **«Указания исполнителю»** и явное подтверждение новой попытки. Только этот
  запуск вызывает модель снова. Предыдущий материал и расходы сохраняются.
- **«Отклонить и завершить»** — завершить задачу без приёмки; новой попытки
  этой задачи после такого решения нет.

Форма **«Новая попытка»** требует отдельного подтверждения и при локальном
тарифе 0. Кнопка **«Запустить новую попытку»** не меняет сохранённый профиль
и не подключает платный API. Смотрите точную информацию о тарифе результата.

Нулевая сумма может сопровождаться ненулевым числом операций, ожидающих
сверки. Это сохраняемая неопределённость, а не повод повторить неизвестное
действие или обнулить историю. Принятие текста не подтверждает окончательный
счёт поставщика.

## 7. При необходимости прочитать материал через MCP

Нужен отдельно подготовленный HTTPS MCP-сервер и проверенный оператором
профиль чтения. Он не появляется после установки RunVerge. Настройте его по
[MCP-READ.md](MCP-READ.md), установите через `install-tool` и передайте worker
нужную переменную ключа, если она указана в профиле. Обычная регистрация
сервера не включает автоматическое выполнение.

До приёмки черновика откройте в задаче **«Действия»**, выберите зарегистрированный
инструмент и его точные JSON-аргументы. Последовательно проверьте намерение,
подготовьте действие с резервом, согласуйте его и отдельно подтвердите запуск.
Если профиль требует другого согласующего, решение должен дать другой
уполномоченный участник; один владелец не заменяет это требование.

Прочитанные блоки сохраняются как массив строк в отдельном артефакте.
Успешное чтение не принимает исходный результат и не доказывает истинность
данных. Для первой проверки достаточно выбранного человеком чтения;
самостоятельный выбор инструмента настоящей моделью этим не проверяется.

## Если что-то не работает

| Наблюдение | Следующий шаг |
|---|---|
| `DATABASE_URL is required` | Загрузите свой `runtime.env` в этом терминале; не печатайте строку подключения для диагностики |
| `invalid private model configuration` | Проверьте права 0600, владельца файла, отсутствие ссылки, точные JSON-поля и корректность значений |
| После входа нет агентов | Это нормально для нового `bootstrap`: создайте и опубликуйте агента |
| Нет нужной модели | Проверьте успешный `install-model`, правильную организацию и активный профиль; переоткройте форму агента |
| Задача остаётся в очереди | Проверьте терминал worker и то, что он использует ту же базу; не создавайте дубликаты задачи для проверки |
| Модель не отвечает | Проверьте управляемый вами сервер, точное имя модели, порт и окружение worker; неизвестный вызов не пересылайте повторно |
| Новая попытка недоступна | Проверьте предел попыток, срок задачи, актуальный доступ и сохранённые финансовые блокировки |
| После обновления страницы потерян вход | Введите прежние организацию и токен; данные задачи находятся в PostgreSQL |

Для чтения доступных возможностей без обращения к модели:

```sh
/absolute/runverge-installation/bin/platform capabilities --url http://127.0.0.1:8080 --credentials /absolute/runverge-private/bootstrap.json --json
/absolute/runverge-installation/bin/platform doctor --catalog --json
```

`capabilities` читает каталог платформы и текущих полномочий. `doctor --catalog`
показывает локальный справочник подсказок даже без базы и сети; это не проверка
здоровья установки. Обычный `doctor --url ... --credentials ... --json`
исследует настройки configuration plane, но не вызывает модель и не доказывает
работоспособность профиля, установленного через `install-model`.

Для остановки завершите свои процессы server и worker через Ctrl+C в их
терминалах. При следующем запуске загрузите тот же приватный файл и запустите
те же `serve` и `worker`; повторять установку и `bootstrap` не нужно.
Сохранность после перезапуска не заменяет резервное копирование. Полноценное
восстановление, автозапуск служб, обновления и независимая пользовательская
приёмка ещё не завершены; актуальные условия выпуска перечислены в
`docs/ALPHA-RELEASE.md` исходного репозитория.

## Сравнить две попытки

Для первого прохода используйте [короткое задание с готовыми фактами](../examples/alpha-first-task.md). PostgreSQL 18 и Ollama устанавливает и обслуживает оператор заранее: это не установка без предварительной настройки.

В разделе «Материалы» две попытки сохраняются как два отдельных артефакта. Оба могут называться `model-candidate.txt` и иметь версию артефакта 1; отличаются их ID и время создания. Скачайте их и переименуйте в `draft-1.txt` и `draft-2.txt` для сравнения. Просмотр рядом и переход версии одного файла v1→v2 здесь не заявлены.
