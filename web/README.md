# Workspace UI

Русский интерфейс React + TypeScript. Использует настоящий API по контракту `../contracts/README.md`. Демонстрационных данных и подмены ошибок фиктивным успехом нет.

## Запуск

Требуется Node.js 22.12+ (проверено на Node.js 24) и pnpm.

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm dev
```

Откройте `http://127.0.0.1:5173`. Vite передаёт `/api` и `/auth` на `http://127.0.0.1:8080`. Это режим bootstrap-разработки. Для SSO обслуживайте production `dist/` и API с одного HTTPS origin: обычный HTTP dev proxy не подтверждает безопасный профиль cookies/Origin/redirect. Настройка сервера описана в профиле OIDC.

`GET /auth/config` определяет способ входа. При выключенном OIDC форма принимает bootstrap-токен и организацию: токен отправляется только в `Authorization`, cookie не отправляются. При включённом OIDC доступны вход через организацию, выбор доступной организации, ротация и выход. Используются HttpOnly session cookie и CSRF token в памяти; JavaScript не получает секрет сессии. Ошибка определения способа входа видима и не вызывает автоматического переключения на другой способ.

Токен Bearer хранится только в памяти страницы и не переживает перезагрузку. В localStorage записывается только идентификатор организации. При SSO после перезагрузки сессия проверяется сервером. Автоматическое перенаправление API-запросов запрещено; авторизация выполняется обычной навигацией формы POST. Внешний API требует HTTPS и серверной CORS-конфигурации; режим SSO работает только с `/api/v1` этого origin.

```sh
pnpm typecheck
pnpm test
pnpm build
```

Сборка создаётся в `dist/`. Runtime не обращается к внешним шрифтам, CDN или аналитике.

## Возможности

- Создание и список задач с фильтрами, поиском по загруженным строкам и курсорной пагинацией.
- Статус, причина ожидания, результат, расходы, резерв и остаток бюджета.
- Журнал событий с серверным sequence-cursor; материалы показываются обычным текстом, HTML не исполняется.
- Отмена задачи через API с подтверждением и предупреждением об уже совершённых действиях.
- Создание черновика агента, просмотр инструкций и инструментов, публикация с `expected_version`.
- Выбор активной модели из `GET /api/v1/models`; endpoint и ссылки на секреты в Workspace не передаются.
- Явное обозначение `fixture:*` как тестового исполнителя, без заявления о наличии работающей LLM.
- Идемпотентные мутации: неоднозначный сетевой сбой сохраняет ключ для повторения того же запроса в текущем подключении. После успешной операции следующее намеренное создание получает новый ключ.
- Суммы вводятся в USD и преобразуются в целые micro-USD без умножения с плавающей точкой. Фактические суммы из API читаются как decimal strings, остаток и шкала вычисляются через bigint. Права и бюджеты всегда повторно проверяет сервер.

## Текущие ограничения

Интерфейс использует контракт0.10.0. Работают команды агентов и дерево задач,
версии материалов с конфликтом/ручным слиянием, согласования инструментов,
явное продолжение модели, ограниченная автоматизация и управление участниками.
Экран «Безопасность» управляет политикой входа, служебными аккаунтами и метаданными
ключей. Смена способа входа требует серверной готовности и настоящей сессии
человека-владельца у доверенного OIDC-провайдера. Секреты выдаются отдельно на
доверенном сервере; UI их не запрашивает. SCIM и реальный корпоративный IdP ещё
не приняты. Provider Edition, полная административная настройка и
независимые испытания удобства остаются впереди. Realtime/offline sync не заявлены.
Клиентская валидация помогает заполнить формы; граница безопасности — сервер.

Текущие результаты: код0.9 и ограничения (internal historical reference omitted),
фактическое состояние реализации.
Ниже сохранены датированные исторические проверки; они относятся к указанным
в них версиям и не заменяют текущую приёмку всего продукта.

## Проверка с настоящим API и worker

23 октября 2026, 15:41 MSK: браузерный smoke в Chromium прошёл на сервере и worker, использующих PostgreSQL. Браузер создал агента, опубликовал его, создал задачу и дождался `succeeded`. Проверены:

- Точное совпадение результата и текстового артефакта с ответом тестового `fixture:echo`.
- Происхождение артефакта: `adapter=fixture:echo`, `verified=true`, `verification=exact_goal_echo`, `synthetic_cost=true`.
- Расход ровно 1000 micro-USD, резерв 0, бюджет 10000 micro-USD. В UI ненулевой расход отображается как `0,001 $`, без округления до нуля.
- События `task.created`, `operation.claimed`, `cost.settled`, `task.succeeded`; в событии расхода также явно указан синтетический учёт.
- Desktop 1440 px и mobile 390 px, без горизонтального переполнения документа и ошибок JavaScript.
- Токен не записан в localStorage/sessionStorage; после отключения и перезагрузки нужен новый вход.

Это проверка реального пути UI → API → PostgreSQL → worker → артефакт, **с тестовым исполнителем и условным расходом**. Она не подтверждает подключение LLM, реальный биллинг, качество агента, SSO, распределённую нагрузку, полный цикл согласований или защиту от всех классов атак.

Воспроизводимый сценарий: `scripts/smoke-completion.mjs`. Нужны запущенные сервер и worker, созданный bootstrap-файл и установленный Playwright с Chromium. Playwright — необязательный QA-инструмент; его можно использовать из внешней установки через `WORKSPACE_PLAYWRIGHT_PATH`, без включения в production-сборку.

Из `web/`, когда Playwright доступен обычному разрешению модулей Node:

```sh
WORKSPACE_BOOTSTRAP=../.local/bootstrap.json pnpm test:browser
```

Переменные для отдельной установки: `WORKSPACE_PLAYWRIGHT_PATH` — абсолютный путь к модулю `playwright`, `WORKSPACE_BROWSER_PATH` — путь к Chromium, `WORKSPACE_URL` — адрес сервера (по умолчанию `http://127.0.0.1:8080`). Скрипт создаёт тестовые агента и задачу. Он читает токен из файла только в память, не снимает экран ввода токена и не сохраняет сетевые трассы.

После успешного запуска локальные результаты находятся в `.qa/completion-report.json`, `.qa/task-completed-desktop.png`, `.qa/task-completed-mobile.png`. Эти файлы исключены из Git. Скриншоты проверены визуально; секреты на них отсутствуют. Предыдущий сценарий отмены в `tests/browser-smoke.mjs` требует **остановленного worker**, чтобы задача оставалась в очереди до отмены.

## Проверка браузерного OIDC

23 октября 2026, 18:20 MSK: Chromium smoke — PASS. Использованы собранный Workspace, реальные HTTP-обработчики через TLS, отдельная схема PostgreSQL и локальный независимый OIDC fixture. Проверены навигация Code + PKCE, HttpOnly/Secure/SameSite cookie, выбор организации из членств, создание/публикация тестового агента, создание/отмена очередной задачи, ротация, выход и перезагрузка. Все четыре мутации API использовали CSRF и не использовали Bearer. На 390 px нет горизонтального переполнения, JavaScript ошибок нет, в browser storage нет секретов.

Проверка выявила и исправила поведение Chromium: `Referrer-Policy: no-referrer` у HTML-документа превращает Origin формы POST в `null`. Теперь Workspace использует `same-origin`, callback/API сохраняют `no-referrer`; строгая проверка Origin не ослаблена. Тест ротации явно дожидается её завершения, прежде чем сравнить cookie.

Воспроизведение из корня репозитория после сборки `web/dist`:

```sh
python3 web/scripts/run-oidc-smoke.py
```

Нужны локальный PostgreSQL из `scripts/dev.py` либо `TEST_DATABASE_URL`, проектный Go, Node, Playwright и Chromium. Для отдельной установки задайте `WORKSPACE_NODE`, `WORKSPACE_PLAYWRIGHT_PATH`, `WORKSPACE_BROWSER_PATH`. Runner запускает Go fixture в отдельной схеме, передаёт браузеру только URL/host/имя организации и затем удаляет схему. Файл metadata и его сигнал завершения временные; secret/DSN туда не записываются.

Только тестовый браузер допускает self-signed TLS fixture через `ignoreHTTPSErrors`. OIDC HTTP-клиент сервера проверяет сертификат fixture через явно заданный CA; production TLS-проверка не отключена. В этой фикстуре нет worker, поэтому проверяется отмена очередной задачи, без заявления о выполнении LLM или настоящем биллинге. Реальный корпоративный IdP и production deployment остаются непроверенными.

Локальные артефакты: `.qa/oidc-report.json`, `.qa/oidc-desktop.png`. Скриншот просмотрен: секретов и формы ввода токена на нём нет. Текущий сценарий не пишет сетевые traces и не печатает cookie; диагностические HTTP-сведения ограничены pathname/status без query. Эти QA-артефакты исключены из Git.
